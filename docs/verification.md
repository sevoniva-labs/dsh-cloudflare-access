# 测试与验收

## 自动化检查

```sh
npm ci
npm run check
npm pack --dry-run
```

`npm run check` 执行类型检查、测试与构建。`dist/` 随源码提交，构建后不应存在未提交的差异。

| 测试范围 | 验证内容 |
| --- | --- |
| 网关 | 官方 DSH 认证、HTTP 与 WebSocket 转发、Host/Origin 限制、控制接口隔离 |
| JWT | 签名、issuer、audience、有效期、身份字段及邮箱白名单 |
| 会话 | 退出登录、浏览器租约、过期会话恢复、不自动重放请求 |
| 配置 | 资源冲突、策略回读、写入顺序、失败恢复、归属检查与清理 |
| 生命周期 | 插件加载与卸载、正常重启、实例锁、凭据不写入状态文件 |
| 客户端 | 插件注册与导航名称 |

Cloudflare 资源测试使用模拟 API；网关测试使用官方 DSH 连接模块。自动化测试不等同于实际 Cloudflare 部署验收。

## 集成验收

使用独立 `DSH_HOME`、独立端口和专用测试子域名，例如 `harness-test.example.com`。不要复用正在服务的部署。

1. 通过插件设置页面创建 Access 应用、访问策略、Tunnel 和代理 DNS。
2. 确认未登录请求进入 Access 登录流程，未授权身份无法访问。
3. 完成浏览器登录，检查身份显示、页面刷新和提供方目录加载。
4. 在网页内浏览并选择主机测试目录，不应启动本机文件选择窗口。
5. 发起一次不使用工具、不修改文件的模型请求，检查实际回复。
6. 重启 DSH，验证连接器、入口和模型请求恢复。
7. 验证退出登录及过期会话提示，不应发生循环重定向。
8. 停用并删除测试部署，回读确认 DNS、Tunnel、Access 应用和运行 Token 文件已清理；共享 IdP 保留。

如使用设备检查，应另外验证合规设备、未注册设备、失效设备和设备撤销。邮箱认证不能替代设备验证。

## 平台与验收边界

- 当前本机与公网集成验证基于 macOS、Node.js 22、官方 DSH 0.1.6-alpha.2，以及已安装的官方 cloudflared。
- Linux、连接器自动下载、强制断电、实际设备检查和长期稳定性需要独立验证。
- 主机目录访问仍受操作系统权限约束。
- 官方运行时的其他本地修改不属于本插件测试范围；应使用干净的 DSH 环境复核兼容性。
