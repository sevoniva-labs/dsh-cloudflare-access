# 测试与验收

## 自动化检查

```sh
npm ci
npm run check
npm pack --dry-run
```

`npm run check` 执行类型检查、测试与构建。`dist/` 随源码提交，构建后不应存在未提交的差异。

| 测试范围 | 验证内容 |
| --- | --- |
| 网关 | 官方 DSH 认证、HTTP 与 WebSocket 转发、Host/Origin 限制、控制接口隔离 |
| JWT | 签名、issuer、audience、有效期、身份字段及邮箱白名单 |
| 会话 | 退出登录、浏览器租约、过期会话恢复、不自动重放请求 |
| 配置 | 资源冲突、策略回读、写入顺序、失败恢复、归属检查与清理 |
| 生命周期 | 插件加载与卸载、正常重启、实例锁、凭据不写入状态文件 |
| 客户端 | 插件注册、导航名称、单一恢复流程、瞬时/持续断网、凭据轮换、后台恢复、权限拒绝、停止后的回调清理 |
| 模型编辑 | 官方模型页适配、主机只读状态、失败与并发回读、未知前端结构不改写、认证后 JS 响应适配 |

Cloudflare 资源测试使用模拟 API；网关测试使用官方 DSH 连接模块。自动化测试不等同于实际 Cloudflare 部署验收。

### 会话恢复回归

`tests/session-recovery.test.ts` 用虚拟时间验证八小时、八次凭据轮换；这不是八小时真实浏览器驻留测试。

隔离浏览器验收可运行 `npm run test:browser`，需要可用的 Playwright 与 Chromium。也可通过 `PLAYWRIGHT_MODULE`、`PLAYWRIGHT_EXECUTABLE` 指定已有测试运行时。测试只在随机 loopback 端口启动模拟入口和插件网关，不使用真实账号、线上任务或模型额度。

浏览器检查包括：网络故障后恢复、受保护回调的静默认证、独立窗口交互登录、拒绝访问不循环跳转。每步核对原页面未导航、输入草稿未丢失、命令未重复提交。Cloudflare 会话行为由模拟入口控制，真实 SSO、浏览器 Cookie 策略和长期驻留仍需线上验收。

连接替身必须在 `reconnect()` 时同步通知 `connecting`，再异步通知 `connected`，不能直接跳到已连接。浏览器用五秒握手验证恢复流程不会反复取消正在建立的连接；单元测试覆盖原生状态通知、前台事件和心跳并发。

正式升级后，应保持一个浏览器标签页跨越应用会话期限，并测试断网与标签页挂起后的恢复。不得为了验收暂停正式任务、撤销用户的有效会话或发送额外模型请求。

## 集成验收

使用独立 `DSH_HOME`、独立端口和专用测试子域名，例如 `harness-test.example.com`。不要复用正在服务的部署。

1. 通过插件设置页面创建 Access 应用、访问策略、Tunnel 和代理 DNS。
2. 确认未登录请求进入 Access 登录流程，未授权身份无法访问。
3. 完成浏览器登录，检查身份显示、页面刷新和提供方目录加载。
4. 在网页内浏览并选择主机测试目录，不应启动本机文件选择窗口。
5. 发起一次不使用工具、不修改文件的模型请求，检查实际回复。
6. 重启 DSH，验证连接器、入口和模型请求恢复。
7. 验证退出登录及过期会话提示，不应发生循环重定向。
8. 停用并删除测试部署，回读确认 DNS、Tunnel、Access 应用和运行 Token 文件已清理；共享 IdP 保留。

### 模型编辑回归

1. 从 Access 域名进入设置，确认“添加自定义提供方”及已有提供方的编辑按钮可用。
2. 创建不含密钥的临时提供方，保存后回读主机设置确认已落盘；删除该临时配置。
3. 编辑已有提供方的显示名称，确认保存成功，其他模型参数和凭据引用不变。
4. 重新加载页面，确认配置仍在；不应要求开启全局 loopback 或暴露 Cloudflare 管理接口。
5. 使用测试凭据完成真实模型请求，分别验证 API 响应和 Harness 原生流式会话。不要把测试凭据、对话和部署信息放入仓库。

如使用设备检查，应另外验证合规设备、未注册设备、失效设备和设备撤销。邮箱认证不能替代设备验证。

## 平台与验收边界

- 当前本机与公网集成验证基于 macOS、Node.js 22、官方 DSH 0.1.6-alpha.2，以及已安装的官方 cloudflared。
- Linux、连接器自动下载、强制断电、实际设备检查和长期稳定性需要独立验证。
- 主机目录访问仍受操作系统权限约束。
- 官方运行时的其他本地修改不属于本插件测试范围；应使用干净的 DSH 环境复核兼容性。
